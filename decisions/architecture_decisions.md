### 2026-08-06：共享 AI 大脑架构设计

**背景**：有两台电脑（台式机 Win11 + 笔记本）使用 Claude Code，需要共享项目经验和技术知识。每台机器独立跑 Agent，但需要访问同一份"外部记忆"。

**决策**：使用 GitHub 仓库 `Doo-ai-brain` 作为共享知识库，纯 Markdown 格式，工具无关。

**考虑过的备选方案**：
- 方案 A：CC 内置 memory 格式同步 → 否决，绑定特定工具，Hermes 等无法读取
- 方案 B：向量数据库 / RAG 系统 → 否决，第一版过度设计，维护成本高
- 方案 C：GitHub 仓库 + Markdown → 选中

**理由**：
- 任何 AI Agent 都能 `git clone` 后直接读取 Markdown
- Git 天然支持版本控制和双向同步
- 结构简单、无需额外基础设施
- 人类也能直接浏览和编辑

**后果**：
- 确定了以 Markdown + Git 为核心的同步架构
- 手动触发 `/brain-sync`（第一阶段不用 hook）
- Hermes（未来）可直接消费同一仓库
- 知识内容独立于 Claude Code 格式

### 2026-08-05：Metis 晶粒度面积法 — 圆形视场（798 μm）

**背景**：原面积法统计整张图片的所有晶粒，但 GB/T 6394 标准要求限定圆形视场（模拟显微镜目镜视场），避免图片边缘的不完整晶粒影响统计。

**决策**：在 `GrainSizeAreaMethod.cs` 中引入圆形视场，直径固定 798 μm（对应 100× 放大下的标准视场），圆心默认图片中心。

**关键设计**：
- `FovCenter`、`FovRadiusPx` 使用可空参数（默认 null），不传参数时行为不变，向后兼容所有现有调用方（BLT/DHTG/IMC）
- 圆外掩膜清零（不产生连通域），圆截断晶粒权重 0.5（与原图边缘晶粒规则一致）
- 分母从整图面积改为圆面积 πr²（否则评级系统性偏高）

**后果**：面积法评级更符合标准。截点法（`JLDAnalysis_BG`）已用圆截点法，无需改。`JLDAnalysis_Double`（双峰）尚未加圆形视场（待用户需求）。

### 2026-08-05：GB/T 6394 B.5 合并统计 vs 简单平均

**背景**：截点法原来对多个视场「各图求 Ī → 取平均 Ī → 算 G」，但 GB/T 6394-2017 附录 B.5 要求「合并统计」——ΣP/ΣL_T 算全局 Ī，而不是各 Ī 的平均。

**决策**：改为 B.5 合并统计：`Ī(全局) = ΣL_T / ΣP`，`G(全局) = -6.643856 × lg(Ī_mm) - 3.288`。保留 `global_average_intercept` 为视场简单平均（方便用户对比）。新增 `global_average_section_points`（ΣP/ΣL_T×1000，个/mm）。

**后果**：评级更准确（合并统计按截点数加权，大视场/多截点的图权重更高）。需用户用测试图验证数值变化。

### 2026-08-06：置信区间格式 — B.6 不确定度

**背景**：`results.ai` 的 `global_confidence_interval` 原来输出 `{low, high, confidence_level}` 三字段对象，用户要求改为单个数值（± 值）。

**决策**：按 B.6 公式，从已有 %RA 换算晶粒度不确定度：`ΔG = 6.643856 × lg(1 + %RA/100)`，输出为单个 `double` 值（保留 2 位小数）。

**后果**：输出格式简化，API 消费者不需要解析嵌套对象。原 `globalGLow/globalGHigh` 变量移除（不再使用）。


### 2026-08-23：面积法全局统计口径（%RA / ΔG）

**背景**：HQL 面积法结果此前只有平均/最大/最小级别，缺相对误差与置信区间；用户要求与截点法（附录 B.2-B.6）对称补齐，并给出照片公式 `G = 3.321928·lg(N_A) - 2.954`。

**决策**：
- 统计对象 = 每张图的 N_A（单位面积晶粒数），**不是 G 本身**（与截点法统计 Ī 而非 G 对称）
- 样本标准差 n-1 → t 查表 95%CI → %RA = ci95/mean×100
- ΔG = 3.321928 × lg(1 + %RA/100)（面积法公式系数；截点法 6.643856 的来源：G 对 lg 的系数是 2×3.321928）
- 输出字段严格只加 `global_relative_error` + `global_confidence_interval`（用户明确不要标准差）
- NA≤0 的图不参与统计（对称截点法 P>0）

**后果**：HQL `JLDAnalysis_Area.cs` 292→408 行（纯增量 115 行）；DHTG 移植同款。待 VS 编译 + 实图验证数值。

### 2026-08-23：DHTG 面积法模型号硬编码 1001/24

**背景**：给 DHTG 模块移植面积法（`JLDAnalysis_Area` + `GrainSizeProc.RunForArea`）。HQL/宝钢版 RunForArea 硬编码 `SegmentImage(..., 1001, 24)`；DHTG 其他方法（Run/RunCircle/RunNCircles 等）用配置化 Category/Item 且默认 1001/004。

**决策**：RunForArea 模型号与 HQL/宝钢一致**硬编码 1001/24**（用户拍板），不采用"移植时顺手配置化"的中间方案——避免配置模型与面积法要求不符时静默用错模型，先保证三模块行为一致。

**后果**：DHTG 面积法固定使用 HQL 同款晶界分割模型（AI 服务需可用）；截点法等仍配置化不受影响。备份 `_fix_backup_20260823_dhtg_area`，待 VS 编译 + 实图验证。
