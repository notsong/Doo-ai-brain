# 工作风格

> 我的工作方式、沟通偏好，以及如何与 AI Agent 协作。

## 沟通风格

- 中文为主，技术术语保留英文
- 直接、简洁，不喜欢废话
- 做决定前展示推理过程
- 不确定就问，不瞎猜

## 开发流程

- **先规划后编码**：复杂功能先出方案再动手
- **增量验证**：骨架 → 内容 → 信号，每阶段都要能跑
- **代码审查**：每次重要修改后必须审查
- **提交规范**：遵循约定式提交（Conventional Commits）
- **经验沉淀**：完成任务后 `/brain-sync` 记录有长期价值的内容

## AI Agent 偏好

- 直接、简洁、讲到点子上
- 展示推理过程后再做决定
- 不确定就问，不要瞎猜
- 能跑的代码优于完美的代码
- 中文化所有面向人类的文档

- 系统：Windows 11
- GPU：NVIDIA（支持 CUDA 11.3+）
- 主要开发机器，模型训练和打包部署都在这里

### 笔记本
- 系统：待配置
- 用于移动/远程办公，通过 Doo-ai-brain 同步知识

## 跨机器工作模式

### 共享大脑同步

使用 GitHub 仓库 `Doo-ai-brain` 作为两台机器之间的知识桥梁。

**台式机（主力）→ 仓库**：
- 完成重要任务后执行 `/brain-sync`
- Agent 总结 → 更新 Markdown → git push

**笔记本 → 仓库**：
- 开始工作前 `git pull` 获取最新知识
- 同样可以贡献经验并 push 回来

**两个 Hermes 实例（大H/小H）**：
- 台式机 = 大H（主力长期大脑），笔记本 = 小H（本实例）
- 两个实例都是同一知识库的消费者和贡献者：工作前 `git pull`，完成后按协议更新 Markdown 并 `git push`
- Claude Code 作为编码执行助手独立工作，用 `/brain-sync` 贡献经验

**关键原则**：
- 不是所有任务都需要同步，只记录有长期价值的内容
- 仓库是知识库，不是日志或聊天记录
- 纯 Markdown，不绑定任何特定 AI 工具
